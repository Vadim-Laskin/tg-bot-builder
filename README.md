# Flowbase — конструктор Telegram-ботов

Блочный визуальный редактор сценариев для Telegram-ботов. Тёмная/светлая
тема, неограниченное число ботов на аккаунт, вкладка «Шаблоны» отдельно от
редактора.

## Статус: фаза 2 — Supabase (Auth + БД) подключены

Данные (боты, флоу, шаблоны) и вход в аккаунт теперь идут через Supabase
вместо `localStorage`. Приложение теперь мультипользовательское: чужие
боты не видны (RLS-политики на уровне Postgres, не только в UI).

### Настройка Supabase (один раз)

1. Создайте проект на [supabase.com](https://supabase.com).
2. В **SQL Editor** выполните целиком файл `supabase/schema.sql` из этого
   репозитория — он создаёт таблицы `profiles`, `bots`, `flows`,
   `templates`, триггер на автосоздание профиля и все политики RLS.
3. В **Project Settings → API** скопируйте `Project URL` и `anon public`
   ключ.
4. Скопируйте `.env.example` в `.env` и вставьте туда эти два значения.
5. `npm install && npm run dev`.
6. Зарегистрируйтесь через форму входа в приложении (email + пароль).
7. Чтобы сделать себя админом (нужно для вкладки «Шаблоны» → «Добавить
   шаблон»), выполните в SQL Editor:
   ```sql
   update public.profiles set is_admin = true where email = 'вы@example.com';
   ```

### На Netlify

Те же две переменные (`VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`) нужно
добавить в Site settings → Environment variables — Vite вшивает их в сборку
на этапе `npm run build`.

Если по умолчанию в Supabase включено подтверждение почты — после
регистрации нужно перейти по ссылке из письма, иначе вход не сработает.
Отключить это можно в Authentication → Providers → Email (для тестового
проекта это обычно удобнее).

## Что уже реализовано (фаза 1 — редактор + движок)

Реализовано и работает **прямо в браузере, без бэкенда**:

- Холст на React Flow: перетаскивание блоков из палитры, соединения,
  панель свойств справа.
- 9 типов блоков (см. ниже) — единый источник правды в
  `src/engine/blockDefs.js`.
- Framework-agnostic движок выполнения флоу (`src/engine/flowEngine.js`) —
  умеет ходить по графу, ветвиться по условиям, звать под-цепочки.
- Панель «🧪 Тест» в редакторе — прогоняет флоу через движок с
  заглушками вместо реального Telegram/Groq, чтобы проверить логику сразу.
- Неограниченное количество ботов, у каждого — основной флоу + сколько
  угодно цепочек (chain-флоу).
- Вкладка «Шаблоны» (вне редактора) — админ (`profiles.is_admin` в
  Supabase) может опубликовать флоу любого своего бота как шаблон;
  остальные создают из него нового бота в один клик.
- Тёмная/светлая тема с переключателем, без "мигания" при загрузке.
- Адаптив под телефон: палитра блоков и панель свойств становятся
  выдвижными шторками (открываются кнопкой «+ Блок» и тапом по блоку на
  холсте), добавление блока на мобильном — тапом по блоку в палитре
  (HTML5 drag-and-drop не работает на тачскринах, поэтому есть и такой
  способ — он же работает и на десктопе как быстрая альтернатива перетаскиванию).
- Регистрация/вход и все данные — через Supabase (см. настройку выше).

```bash

```

## Деплой на Netlify

```bash
npm run build
```

подключить репозиторий к Netlify — команда сборки и папка публикации
подхватятся автоматически.

## Блоки

| Блок | Категория | Что делает |
|---|---|---|
| Заметка | Контент | Комментарий на холсте, не выполняется |
| Событие | Логика | Точка входа: команда, текст, кнопка, расписание |
| Сообщение | Контент | Текст + кнопки пользователю |
| Сообщение с ИИ | Контент | Ответ через Groq по промпту |
| Действие | Логика | HTTP-запрос / typing / пауза |
| По условию | Логика | Ветвление да/нет по переменной или тегу |
| Цепочка | Структура | Вызов переиспользуемого под-флоу |
| Изменение переменной | Данные | set / increment / clear |
| Изменение тегов | Данные | добавить / убрать тег |

Добавить новый блок = добавить одну запись в `blockDefs.js` и (если нужна
особая логика выполнения) обработчик в `nodeHandlers.js`. Палитра,
карточка на холсте и панель свойств уже читают список блоков динамически
— почти всегда правки в одном месте достаточно для простых блоков; для
специфичных полей в панели свойств (`PropertiesPanel.jsx`) нужно добавить
свою секцию формы.

## Фаза 3 — бэкенд для самого бота (следующий шаг)

Auth и хранение данных уже на Supabase. Осталось подключить сам приём
сообщений от Telegram:

1. **Netlify Functions** (`netlify/functions/`, папка уже создана):
   - `telegram-webhook.js` — принимает апдейты от Telegram, вызывает
     тот же `runFlow()` из движка, но с реальным `api` (настоящие вызовы
     Telegram Bot API и Groq вместо заглушек из `mockApi.js`).
   - `set-webhook.js` — при сохранении токена бота регистрирует webhook
     в Telegram на адрес функции.
2. **Шифрование секретов** — токены ботов и Groq-ключи сейчас лежат в
   таблице `bots` в открытом виде (доступ ограничен RLS, но не
   зашифрован). Для продакшена — перевести на Supabase Vault и не
   отдавать значения на клиент целиком после сохранения.

## Структура проекта

```
supabase/
  schema.sql       — таблицы, триггеры и RLS-политики (выполнить в Supabase SQL Editor)
src/
  lib/supabaseClient.js — клиент Supabase (URL/key из .env)
  engine/          — движок выполнения флоу (без React, переиспользуем на бэкенде)
    blockDefs.js     — метаданные всех блоков (общий источник правды)
    flowEngine.js    — обход графа
    nodeHandlers.js  — что делает каждый тип блока
    mockApi.js       — заглушки IO для превью в браузере
  store/           — zustand-хранилища, читают/пишут в Supabase
  components/      — UI: холст, палитра, панель свойств, список ботов, шаблоны, авторизация
netlify/functions/ — бэкенд для приёма Telegram-апдейтов (фаза 3, пока план в README там же)
```
